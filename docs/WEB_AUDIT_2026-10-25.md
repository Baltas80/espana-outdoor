# Auditoría de la web España Outdoor — 25 de octubre de 2026

## Alcance revisado

Revisión estática de `site/index.html`, `site/styles.css`, `site/app.js`, `site/app.html`, `site/mapa.html`, `site/rutas.html`, `site/route-catalog.js`, `site/data/routes-catalog.json`, `site/seguridad.html`, `site/tienda.html`, `site/tienda.js`, `site/robots.txt`, `site/sitemap.xml` y `site/manifest.webmanifest`.

## Cambios aplicados en esta rama

- Se retiró de la portada una URL de imagen de CloudFront con firma temporal caducable. La hero usa una URL permanente de Unsplash ya utilizada por el sistema visual; conserva carga prioritaria y recorte responsive.
- Se añadió canonical en la portada y se mejoraron los metadatos para buscadores y vistas previas sociales.
- Se añadió un buscador real en la portada que envía la consulta como `?localidad=` a `rutas.html`. El catálogo inicializa el filtro con ese parámetro y ofrece un estado de error más claro cuando no carga el JSON.
- Se mejoró el menú móvil para cerrar con Escape, devolver el foco al botón y anunciar el estado del menú mediante su etiqueta accesible.
- Se moderaron las afirmaciones de disponibilidad de mapas offline, número de rutas y navegación GPS; el texto distingue funciones existentes en la base del producto de servicios sujetos a configuración.
- Se aclaró que la página `mapa.html` informa sobre el enfoque cartográfico y no constituye un visor web operativo configurado.
- Se añadió en la página de seguridad una advertencia explícita: los módulos SOS/Rescue Link no deben considerarse un servicio de rescate y no sustituyen al 112.

## Hallazgos de la revisión

### Buscador y catálogo de rutas

- La página `rutas.html` tiene controles de texto, fuente, tipo y recorrido, y un script de filtrado local.
- El catálogo `site/data/routes-catalog.json` contiene **6 rutas** y declara `last_verified: 2026-09-28`. Es un catálogo inicial, no demuestra una cobertura nacional exhaustiva. Hay que volver a verificar y ampliar sus datos antes de anunciar miles de rutas.
- La búsqueda principal depende de ese catálogo estático. No es una consulta dinámica en tiempo real a CNIG/FEDME.

### Tienda

- `tienda.js` lee el token público de Storefront desde `window.ESPANA_OUTDOOR_SHOPIFY_STOREFRONT_TOKEN`.
- No se encontró `site/shopify-config.js` en la rama auditada ni una declaración del token en el código revisado. El propio script muestra el estado “Shopify aún no está configurado en el despliegue” si falta el token. Por tanto, no se debe presentar el catálogo/checkout como verificado.
- No se insertaron tokens inventados ni credenciales privadas.

### Legal y privacidad

- No se localizaron páginas `privacidad.html`, `aviso-legal.html` ni `cookies.html` en `site/`, y el pie de la portada no las enlaza.
- No es responsable publicar un aviso legal completo sin conocer la identidad legal del responsable, NIF/NIE cuando corresponda, domicilio y contacto, ni confirmar el alojamiento efectivo y las cookies/servicios desplegados. Este punto sigue **pendiente de los datos reales del titular**; no se han inventado datos ni textos jurídicos para aparentar cumplimiento.

### SEO y recursos visuales

- Existen `robots.txt` y `sitemap.xml`; el sitemap incluye las páginas de la web revisadas y una ficha dinámica de ruta.
- La portada ahora declara canonical. Debe comprobarse el canonical de cada página y revisar las URLs sociales tras el despliegue.
- Las fotografías de varias páginas siguen cargándose desde Unsplash/Wikimedia. La portada ya no depende de una URL de imagen firmada temporal, pero no se ha realizado una prueba HTTP real de todas las fuentes externas ni una descarga local de las fotografías.

## Validaciones

**Comprobado estáticamente:** el JSON del catálogo se puede parsear; existen la referencia a `rutas.html` y su script de filtrado; la búsqueda ahora lee `localidad` de la URL; la portada ya no contiene la URL firmada de CloudFront; los metadatos canonical están presentes; el código del menú incluye cierre con Escape; existen `robots.txt` y `sitemap.xml`.

**No verificado en esta auditoría:** ejecución de clics en un navegador real, carga HTTP de cada fotografía/servicio externo, mediciones Lighthouse/Core Web Vitals, pruebas en varios móviles, funcionamiento físico del APK Android o la operación real de SOS, GPS y routing. No debe afirmarse que esas pruebas han pasado.

## Bloqueos antes de considerar la web terminada

1. Proporcionar y publicar de forma segura los datos legales y de privacidad del responsable; revisar cookies/analítica y alojamiento.
2. Completar el catálogo de rutas con una ingestión reproducible y fuentes verificadas; actualizar la fecha de revisión.
3. Configurar Shopify en el despliegue y comprobar catálogo, carrito y checkout de extremo a extremo.
4. Probar las imágenes, enlaces externos y menú en móvil; ejecutar Lighthouse y comprobar el sitio desplegado después de integrar esta rama.
5. Validar en un dispositivo Android las funciones que se anuncien como disponibles, en especial cartografía, uso offline, routing y seguridad.

Esta auditoría no equivale a una certificación legal ni a una prueba de aceptación física del producto.
